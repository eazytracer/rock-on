# Workflow: Jam-night event (host & guest)

**Goal:** a host plans a night where people sign up to play (a birthday jam, a backyard gig), with requests and volunteers sorted out before the night.

## Host

1. **Create:** name, date, start and end time, venue. No band needed.
2. **Access:**
   - Visibility: **Public** / **Unlisted** (link or code) / **Private** (invite only).
   - Join code, link, QR.
   - Toggles: **Allow song requests**, **Auto-approve requests**.
3. **Invite:** pick from friends, or share the link or QR.
4. **Lineup:**
   - Add songs: title, artist, optional tuning and key.
   - Drag to reorder; edit and remove.
5. **Requests:**
   - Approve or reject guests' song requests.
   - Approving a request where the guest offered parts raises their hand for those parts.
6. **Co-hosts:** make or remove co-hosts. Co-hosts can manage the lineup and requests.
7. **Cancel:** soft cancel. The event stays visible as cancelled.

## Guest

1. **Join:** by link, code or QR; land on the event.
2. **RSVP:** Going / Maybe / Can't. [Not built]
3. **Request a song:** title and artist, optionally offering parts to play.
4. **Raise a hand** for a part on a lineup song, or withdraw it.
5. **Leave** the event.

## Must

- Counts on each tab: Lineup, Requests (pending count), People.
- People shows each person's status ("Hand up · Bass").
- Clear states: "Requests are closed", "Auto-approve is on".
- The host can't leave their own event.

## Must not

- Offer **Public** visibility unless public events can actually be found. [Future] Browse public events.
- Show casting controls when casting is off (`explorations/casting.md`).
